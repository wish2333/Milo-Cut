## 〇、版本定位与总裁决

### 0.1 需求语义定式（先钉死，避免再跑偏）

本版主题「多层时间线」经三轮澄清，语义定式如下：

> **同一条时间线，按时间先后切成若干「行（row）」，垂直堆叠、同时显示。**
> 行 1 显示 0:00–0:10，行 2 紧接 0:10–0:20，行 3 接 0:20–0:30……
> 在**不缩小缩放级别**（字幕块仍可读）的前提下，一屏同时看到更多字幕、覆盖更宽的时间范围，不用来回横向平移。

明确排除的相邻概念（历史上已被混淆）：

| 概念 | 含义 | 与本版关系 |
|---|---|---|
| ~~多层字幕~~ | 主轨 + N 副轨字幕的堆叠与绑定联动 | **v3.0.1 已交付**，本版不动其语义 |
| ~~多版本时间线~~ | project.timelines 多份 fork 切换对比 | 无关 |
| **多行时间线** | 时间轴自身的分行续接显示 | **本版主题** |

与 v3.0.1 堆叠时间线的关系：**正交组合**。v3.0.1 解决「主轨与副轨在同一时间窗内垂直堆叠」；v3.0.2 解决「同一时间轴切成连续多行、扩大同屏时间覆盖」。两者叠加后的完整形态 = MAW 的「每行内主字幕 lane + 副字幕 lane，行序列垂直续接」排版。

### 0.2 总裁决

1. **MAW 多行时间线的精华是四件套，全部是框架无关的纯逻辑，可整体平移**：
   - **时间→行映射**：行 i 覆盖 `[i×secondsPerRow, (i+1)×secondsPerRow]`，滚动位置与时间互相推导（`waveformTopEdgeMs` / `restoreWaveformTopEdgeMs`，waveform.js:256-273）；
   - **行级虚拟化渲染**：只渲染视口 ±2 行，行 DOM 保留 canvas/字幕块/事件监听增量复用（`renderMultiVisible` :2795-2819、`updateMultiRowLayout` :2730-2759）；
   - **每行播放头**：播放头每行一个元素，只在包含当前时间的行内可见（`positionPlayheads` :5306-5317）；
   - **舒适区自动跟随**：播放行滚出上下边距（48–120px 自适应）才触发滚动，避免抖动（`isMultiRowInComfortZone` :246-254）。
2. **我方唯一的结构性障碍是 `useTimelineMetrics` 的单窗模型**（`viewStart + viewDuration` 一次只描述一个时间窗）。它是 3.0.0 以来的几何中枢，被 7 个子组件注入消费（已逐一核验）——但这恰好意味着：**每行提供一个满足接口形状的 metrics 适配器 + 改造 WaveformEditor 编排层，全链路自动获得多行能力**，这是 3.0.0 架构「metrics 与轨道无关」红利的直接兑现。
3. **不抄的部分**：MAW 的 17k 行手工 DOM 渲染层、layoutTree 模块拖拽系统、四套工作区预设（classic/wave-right/three-fold/cinema）——后者是它的"界面排版"答案，我们取其**信息架构**（分区比例、控件位置、模式切换入口），不取其实现。MAW 把波形设置存进工程文件的「工作区即数据」也暂不跟进（schema 冻结红线）。
4. **深查同时发现 3.0.1 有三处「文档已勾销但代码未闭环」的正确性缺陷**（副轨编辑断链 / 联动 patch 丢层 / 撤销捕获层不符，均经本人二次核验，见 §2.5）——必须在多行化动工前先收口（P0.5 批），否则多行化的行级编辑会建立在断链地基上。
5. 规模判断：前端为主（P0.5 收口 + 几何中枢适配 + 行组件 + 虚拟化 + 手势），后端仅 P0.5 约 100-200 行（多行本体零 schema 变更、零迁移）。总量与 v3.0.1 相当。

## 一、竞品深查：MAW 多行时间线机制

> 本章全部结论附 waveform.js 行号，关键函数已逐段亲读复核。

### 1.1 设置模型与常量

`DEFAULT_SETTINGS`（:168-185）中与行系统相关的字段：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `mode` | `'multi'` | `'multi'` 多行 / `'basic'` 单行（单窗模式，与我们现状同构） |
| `secondsPerRow` | `10` | 每行覆盖的媒体秒数，可选预设 `ROW_PRESETS = [5, 10, 20, 30]`（:148） |
| `rowHeight` | `120` | 行高 px，预设 `ROW_HEIGHT_PRESETS = [64, 80, 96, 120, 144, 168]`（:149） |
| `visibleSeconds` | `20` | basic 模式的单窗时长 |
| `waveformScale` | `1` | 波形纵向振幅缩放（与时间无关） |
| `layoutRows` | `[42,16,42]` | wave-right 工作区**左列**上/中/下三段高度百分比（视频/当前字幕/字幕列表，工作区布局，非行系统） |

常量：`ROW_GAP = 10`（:150，行间距）；`MULTI_ROW_BUFFER = 2`（:154，虚拟化前后缓冲行数）；`PLAYHEAD_DRAG_SEEK_INTERVAL_MS = 32`（:162，拖动播放头 ~30FPS 节流）；`WAVEFORM_ADJUST_DEBOUNCE_MS = 160`（:163）。

**点评**：默认 10s/行、120px 行高——一行放得下一句口播字幕的两行文本，视口（约 800px 高）可同屏 5–6 行 = 50–60 秒内容，字幕文本全可读。这是「看得更多且看得清」的平衡点，值得照抄为默认值。

### 1.2 时间→行映射（核心数学）

- 行 i 的时间区间：`[i × secondsPerRow×1000, min(durationMs, (i+1) × secondsPerRow×1000)]`（`updateMultiRowLayout` :2747-2748）。
- 总行数：`rowCount = ceil(durationMs / rowDurationMs)`（:2737）。
- 内容总高度：`rowCount × (rowHeight + ROW_GAP) − ROW_GAP`（:2739，stride = rowHeight + ROW_GAP）。
- **末行按比例缩短**：最后一行宽度 = `(endMs − startMs) / rowDurationMs × 100%`（:2751）——媒体不满整行时行变窄，直观表达"到这里就完了"。
- **滚动 ↔ 时间互转**：`waveformTopEdgeMs = floor(scrollTop / stride) × rowDurationMs`（:256-262）；恢复时量化到行边界 `restoreWaveformTopEdgeMs`（:264-273）。**滚动条刻度就是时间刻度**，这是多行时间线最优雅的一点：浏览位置天然可持久化、可恢复。

### 1.3 渲染管线与虚拟化

- 入口分派：`render()` → basic 走 `renderBasic()`，multi 走 `renderMulti()`（:2705-2706）。
- `renderMultiVisible(force)`（:2795-2819）：
  - 可视行窗口：`first = floor(scrollTop/stride) − BUFFER`，`last = ceil((scrollTop+clientHeight)/stride) + BUFFER`（:2800-2801）；
  - 窗口未变且非 force 时只更新播放头直接返回（:2802-2805）——滚动静止时零渲染开销；
  - 全量重建时**先完成所有 DOM 变更再统一绘制**（:2809-2818 注释：避免逐行强制同步布局）；
  - 增量路径（:2821-2837）：wanted/existing 两个 Set 做 diff——**滚出的行 `row.remove()`、新进入的行创建并绘制、留在范围内的行保留原 canvas 不重绘**（注释原文："消除滚动时的整体重建卡顿"；缓冲 2 行的注释理由是"字幕快捷键跨行时可以直接复用已绘制的行"）。
- 增量更新 `updateMultiRowLayout`（:2730-2759）：设置变化（行高/每行秒数）时**不重建行 DOM**——已有行保留 Canvas、字幕块和事件监听器，只改 top/height/width 几何，再对受影响行重画。
- **行包络记忆化**：`getWaveformEnvelope`（:3345-3377）以 `{width, startMs, endMs, scale, peaksPerSecond…}` 为 key 缓存在行实例上——同几何重复 drawRow 零重算；dpr 上限 2（:3382）。
- **字幕覆盖层刷新不动 canvas**：`refreshCueOverlay`（:3273-3291）只按行移除并重建字幕块 DOM，**保留行与 canvas**（避免重采样波形）——编辑器常规刷新走这条，只有结构大变才 `renderSegments()` 全量。
- **布局拖拽期性能技巧**（:2699-2704）：divider 拖动中不做全量重建（注释：每帧 14 个 canvas 重绘会卡顿——反推视口内约 12-14 行），只把已有 canvas 位图 CSS 拉伸，松手后由 scheduleRender 恢复清晰重绘。
- 行内内容：`appendGapBlocks` + `appendCueBlocks`（:2891-2892）——静音空隙块与字幕块都是**百分比定位的 DOM 元素**，叠在行 canvas 上，随行宽自适应（:2710-2711 注释明示"字幕块/空隙块/播放头均为百分比定位，会随行宽自动跟随"）。

### 1.4 行内字幕块（"一眼看到更多字幕"的载体）

`appendCueBlocks(row, startMs, endMs)`（:3080-3154+）——每行的字幕块是**百分比定位 DOM + 内嵌文本**：

- **跨行字幕的裁剪与延续**：块按行窗口裁剪（`layoutBlock`），跨越行边界的字幕在两行各渲染一份，CSS 类 `.continues-from-previous-row` / `.continues-to-next-row`（waveform.css:810-817）标记延续边；
- **trim 手柄的行内规则**：左/右手柄只在"该边缘落在本行内"时渲染（`segment.start >= startMs` 才有左柄、`segment.end <= endMs` 才有右柄，:3133-3142）——跨行段不能在延续边上被误 trim；
- 文本 `replace(/\s+/g,' ')` 归一后进 `.waveform-cue-label`；短块截断、悬浮 `title` 给全文（:3106-3112）；
- 每行块扫描从 `firstCueIndexOverlapping(segments, startMs)` 二分起步（:3089），行内顺序 break——每行渲染成本 O(行内段数 + log S)；
- 块状态：selected / active（当前播放且视觉命中）/ disabled（dim 或 hidden 两档）；组徽章、绑定标记挂在块上（:3110-3131）；
- 每行有时间标签 `.waveform-row-time`（waveform.css:503，行首绝对时间）；
- **多字幕 lane 与行的组合**：`.waveform-row.multi-subtitle-row`（waveform.css:516-574）——开启多字幕后，**每个时间行内部再分主/副双 lane**，副轨块半透明底+虚线边区分，轨道徽标 1/2 挂行 `::before/::after`。即：**多行（时间分行）× 每行多 lane（字幕分层）= MAW 的完整形态**，与我们 v3.0.1 堆叠 lanes 是同一语义在不同轴上的展开。

### 1.5 播放头

`positionPlayheads()`（:5306-5317）：

```js
this.renderedRows.forEach((row) => {
  const visible = now >= startMs && now <= endMs;
  playhead.hidden = !visible;
  if (visible) playhead.style.left = `${((now - startMs) / (endMs - startMs)) * 100}%`;
});
```

- 播放头是**每行一个元素**，非全局贯穿——只在当前播放行显示，一行内按百分比定位；
- 拖动播放头 scrub 时 32ms 节流 seek（:160-162），松手补一次精确 seek；
- **行内点击 seek 的双映射语义**：`timeFromPointer`（:3742-3748）钳制在本行（ratio clamp 0-1）；`timeFromPointerUnbounded`（:3752-3758）不钳 ratio——播放头/范围拖拽跨行延伸必须用后者，否则出现"拖到行边缘时间跳到下一行开头"的经典 bug（MAW :4100-4102 注释即为此 bug 的修复记录）。**y 坐标不参与时间换算**（y 只用于双 lane 轨道命中）。

### 1.6 自动跟随（Comfort Zone）

`isMultiRowInComfortZone(rowIndex, scrollTop, viewportHeight, rowHeight)`（:246-254）：

- 舒适边距 `comfortInset = clamp(viewportHeight × 0.2, 48, 120)` px；
- **只在换行时做跟随判定**（`updatePlayback` :5210-5247）：`multiFollowCheckPending || rowIndex !== multiFollowRowIndex` 才检查——同行内只走 positionPlayheads，per-frame 成本压到一次整数比较；
- 滚动量：播放跟随用 `rowIndex × stride − viewportHeight × 0.35`（**35% 偏置**，行落在视口上部 1/3 处）；手动跳转 `revealTime`（:2287-2330）用 45% 偏置更居中，且**目标行已在舒适区则完全不滚**、仅移动播放头（:2323-2328 注释：目标仍在可视行内时不重建 DOM/Canvas）；
- 行越过边距才滚（stride 对齐）；`autoScrolling/autoScrollTarget` 标志防止程序化滚动事件回环（:1548-1553）；
- `multiFollowCheckPending` 标记（:2735, :4001）把跟随检查合并到渲染帧，用户手动滚动后立即取消待执行的自动跟随（`autoScrolling = false; autoScrollTarget = null`，:3999-4000）；**滚动事件协议**（:1546-1559）：`event.isTrusted && !wasAutoScroll` 才置 `manualFollowUntil = now+3000`——程序化滚动不打断跟随；
- **同一舒适区算法是全局交互语言**：字幕列表滚动定位 `scrollCueToCenter` 用同一 20%/48-120px inset（editor.js:8280-8303）——波形行跟随与列表滚动一个心智模型；
- 播放头位于可视行下方时自动跟随滚动（`revealTime`，editor.js:9046；CHANGELOG 1.4.0）。

### 1.7 操作手势表（多行模式）

`handleWheel`（:3996-4044）：

| 手势 | 多行模式行为 |
|---|---|
| 普通滚轮/触控板 | 原生竖向滚动行序列（不 preventDefault） |
| **Ctrl/Cmd + 滚轮** | 循环切换 `secondsPerRow` 预设（5→10→20→30）——**多行模式的"缩放"就是改每行秒数**，改完 `renderMulti()` 全量重排（:4033-4042） |
| **Ctrl/Cmd + Shift + 滚轮** | 循环行高预设（64–168px），不改变时间映射（:4002-4011） |
| **Shift + 滚轮** | 波形振幅缩放，rAF 合并高频事件（:4012-4017） |

行内 pointer 家族（`createRow` 内绑定，:2894-2981）：

| 操作 | 行为 |
|---|---|
| 左键点击空白 | 清除选中 + seek 到该点；按住拖动 = scrub 播放头（`dragPlayhead` 开关，:2955-2959） |
| Shift + 左键拖动空白 | 框选（marquee）字幕块，追加多选（:2937-2948）——选框挂在内容容器坐标系上，对所有可视行做矩形相交命中，**天然跨行**（:3900-3994） |
| Ctrl/Cmd + 左键拖动空白 | 按拖动范围**新建字幕**（先查时间占用，拒绝重叠；预览遇已有字幕停在边界，:2914-2933/:3677-3701） |
| Alt + 左键拖动空白 | 拖出静音空隙范围（:2901-2912，跨行预览 :4835-4875） |
| 中键拖动 | 空隙范围操作（gap 模式开启时，:2897-2899） |
| 双击空白 | 播放/暂停（:2975-2980） |
| 双击字幕块 / 右键 | 编辑 / 上下文菜单（:2975-2981） |
| hover | 指示线 + 悬停预览（pointerenter/move :2961-2964） |

**拖拽跨行安全契约**（`captureRowGeometry`，:3621-3629）：pointerdown 时快照 `{left, width, startMs, endMs}`，拖拽期间即使行被虚拟化重建/滚动，时间换算一律用快照几何（beginCueDrag :4103 注释明确说明此 bug 的成因与修法）——**虚拟化对进行中的交互完全透明**。

basic 模式对照（:4019-4031）：Ctrl+滚轮 = 缩放窗长；普通滚轮 = 窗口平移 12%，且 `manualFollowUntil = now + 3000ms`——**手动操作后暂停自动跟随 3 秒**，这个细节值得照抄。

### 1.8 工作区排版（界面布局系统）

整体结构（editor-template.html）：**双工具栏（文件行 + 工具行，各 ~30px）+ 四模块工作区**——`#editor-workspace` 内是播放器 / 当前字幕编辑面板 / 波形区 / 字幕列表四个模块，5 根 7px 分隔条拖动调比例，**没有传统折叠面板**（折叠语义被"整套工作区切换 + 面板自由停靠"替代）。

`BUILTIN_WORKSPACES`（:204-235）四套内置布局预设：

| 预设 | 波形模式 | 分栏 | 特征 |
|---|---|---|---|
| `classic` | multi | split 60 / column 36 | 右侧整列字幕列表，聚焦列表编辑 |
| `wave-right`（默认） | multi | split 60 / column 30 | 波形区居右整列贯通，左列 = 视频 42%/当前字幕 16%/列表 42% |
| `three-fold` | multi | split 60 / column 30 | 三分屏，波形 `waveformScale: 4` |
| `cinema` | **basic** | split 60 / column 36 | 左上大视频 + 底部整行**单行**波形，振幅 ×5.5 |

- 布局是**模块二叉树**（`{type:"split",direction,ratio,children}` + `{type:"module",id}`，schema `moy.asr.editor.workspace.v1`）+ 三段行百分比 + 分栏百分比的组合；「编辑布局」模式下每个面板顶部浮现拖拽把手，金色落点/绿色插入位预览，支持保存/另存/删除/导出导入 `.workspace.json`；
- **工作区即数据**：每个工作区携带 `waveformMode`、`waveformSettings`、`editorDisplay`（列表/编辑区列显隐）——布局不是 UI 偏好而是随工程走的资产；
- 布局操作有**独立撤销通道**（pushLayoutUndo）：divider 拖动先取快照、首次变化才入栈，一次拖动一条记录；
- 设置持久化是**双层**：① localStorage `moy.asr.waveform.settings.v1`（:554-600，浏览器级默认，`file://` 隐私模式拒绝写入时静默降级）；② **工程文件 `workspace` 字段**（schema `moy.asr.editor.workspace.v1`，含 `waveformSettings`/`waveformMode`/布局树），加载时**工程值覆盖浏览器值**（editor.js:17497/:13917）；服务器版另有命名工作区库与 `workspace.navigation`（波形顶部时间锚点 + 列表 scrollTop，`getNavigationSnapshot/restoreNavigation` :5251-5304，锚点量化到行首）。`normalizeLayoutData`（:503-543）做预设白名单校验、非法值回退默认。
- **我方裁决（有意偏离）**：3.0.2 坚持 schema 冻结红线（零后端 schema 变更），行设置与浏览位置**只入 localStorage**（对位我们 useLaneLayout 的 `milocut:timeline-layout:v1` 先例）；MAW 的「工作区随工程走」记入后续版本池，届时按「project.json 只增带默认值字段」惯例扩展。

时间线区排版细节（与多行系统直接相关）：

- **无独立全局标尺**：多行纸带隐喻下，刻度画在每行 canvas 内，tick 间隔按行长自适应（1s/2s/5s，waveform.js:3410-3415）；每行左上角 `.waveform-row-time` 时间徽章（mono 11px，如 `00:00.0 → 00:10.0`，waveform.css:503-515）；
- 播放头 2px 红（`--wave-playhead`）+ glow，每行一根；鼠标指针线 1px 灰白随 hover；
- 字幕块贴行底排布（multi 模式高 35px、basic 72px），**跨行截断块相接侧去圆角保持视觉连续**（`.continues-from/to` 类的去圆角规则，waveform.css:808-817）；
- 滚动：纵向 `#waveform-scroll`（overflow-y:auto），**横向无滚动**（时间映射行宽）——水平"缩放"由每行秒数承担；
- 波形设置集中在 ⚙️ 浮窗：显示窗口 stepper（basic）、每行长度/每行高度 select、禁用字幕显示（淡化/隐藏）、拖动指针开关等（editor-template.html:1203-1261）；
- **已知槽点**：无全局总览 mini-map，长视频只能逐行滚（详见 3.4 我们的反向设计）。

**点评（对我们最有用的三点）**：
1. **多行/单行是同一组件的两种模式**（mode 开关 + 分派渲染），不是两个组件——保留单行模式作为"电影模式"既满足大屏预览场景，又降低迁移风险（单行模式 = 现状行为的超集）；
2. **"缩放"语义在多行模式下被重定义**为"每行秒数"，横轴不再是无限延展的窗，而是恒定行宽——字幕块文本有确定的可用宽度，可读性有下限保证；
3. 布局预设按**工作流场景**命名（列表编辑/波形右置/三分屏/大荧幕），而非按视觉风格——我们的排版改进应学这个思路。

演进方向旁证（CHANGELOG 1.0→1.5 十余版本）：MAW 的迭代主线是「编辑操作深度（快捷键族/拆分精度/微调）→ 双语与批量工作流 → 辅助层（引导/帮助/反馈）」，每一轮 UI 改动都伴随防呆与性能注释沉淀——多行时间线从 1.0 起就是其编辑深度的地基，从未被推翻重构。

### 1.9 峰值数据供给

reapeaks（REAPER 峰值文件格式）解码 + spectral payload（:5327-5329 testing 出口），按行绘制时对每行时间窗插值采样（`sampleInterpolatedPeak` :5349）。行系统与峰值数据解耦：`drawRow(row)` 只关心该行的 [startMs, endMs] 窗口。

**对我们的意义**：后端 `generate_waveform` 的峰值 JSON sidecar（3.0.0 M11-3）无需变动——多行渲染只是对同一峰值数组做多次窗口采样；若未来上 mipmap 再谈（v2 报告 L 级项维持后置）。

## 三、v3.0.2 实施方案

### 3.0 架构支点：一行 = 一个单窗视图（先说最重要的结论）

对现有代码的关键验证：`WaveformCanvas.drawWaveform`（WaveformCanvas.vue:186-198）纯粹按 `metrics.viewStart / viewEnd / viewDuration` 窗口采样峰值；`TimeMarksLayer` / `SegmentBlocksLayer` / `PlayheadOverlay` / `ScrollbarStrip` 全部只消费注入的 metrics（inject `TIMELINE_METRICS_KEY`，逐组件核验：SegmentBlocksLayer.vue:35/71-73、TimeMarksLayer.vue:10-31、PlayheadOverlay.vue:12-26、ScrollbarStrip.vue:6-30）；PlayheadOverlay 额外注入的 `PLAYBACK_CLOCK_KEY` 在编排层单点 provide，各行共享即可。

> **因此：多行时间线的每一行，本质上就是一个 viewStart = 行起点、viewDuration = 每行秒数的单窗视图。**
> 行组件内部 provide 一个行级 metrics 实例，3.0.0 以来的全部子组件栈**零改动**即可按行渲染。3.0.0「metrics 与轨道无关」的架构红利在这里第二次兑现（第一次是 3.0.1 堆叠 lanes）。

新增的只有编排层：行规格状态、可视行窗口计算、舒适区跟随、手势分发、行设置持久化——全部是 MAW 已验证的纯逻辑（第一章四件套）。

### 3.2 组件与状态设计

```
WaveformEditor.vue（编排层，改造）
├─ 控件栏：模式切换(多行/聚焦) · 每行秒数 select(5/10/20/30) · 行高 select(64-168) · 视口覆盖范围
├─ 行区容器（竖向滚动，内容高 = rowCount×stride−gap）
│   └─ v-for visibleRows (keyed, 视口±2)
│       └─ WaveformRow.vue（新）
│           ├─ provide 行级 metrics（viewStart=i×spr, viewDuration=spr, follow 关闭）
│           ├─ WaveformCanvas（零改动，按行窗口采样）
│           ├─ TimeMarksLayer（零改动，行级标尺）
│           ├─ SegmentBlocksLayer（零改动，行级裁剪 + 延续标记类）
│           ├─ 行播放头（仅当 currentTime ∈ 本行时渲染）
│           └─ [P3] 副轨 lanes（useLaneLayout 每行实例化）
├─ basic 模式分支：现状单窗渲染路径原样保留（含 ScrollbarStrip）
└─ useRowLayout.ts（新 composable）
    ├─ rowSpec: { mode, secondsPerRow, rowHeight }（localStorage 持久化）
    ├─ scrollTop ↔ 时间互转（waveformTopEdgeMs / restore 语义）
    ├─ visibleRows 计算（first/last = 视口 ±2 行缓冲）
    ├─ 舒适区跟随（inset = clamp(viewportH×0.2, 48, 120)，行对齐滚动）
    └─ manualFollowUntil（手动操作后 3s 暂停跟随）
```

关键设计裁决：

- **`useTimelineMetrics` 行级适配器方案**：每行构造满足 `TimelineMetrics` 接口形状的适配器实例（`viewStart = i×spr`、`viewDuration = spr`，follow/zoom watcher 禁用——跟随与缩放是编排层职责，N 个行实例各自 scrollTo 会打架），行组件 provide、子组件零改动消费；**不侵入 useTimelineMetrics 加 mode 分支**（多行机制子代理独立得出同一结论：适配器优于模式分支）
- **拖拽几何快照契约**（MAW `captureRowGeometry` :3621-3629 的 Vue 化）：拖拽状态**上提到 composable/store** 而非组件实例——pointerdown 冻结 `{rowLeft, rowWidth, rowStart, rowSpan}`，pointermove 一律用冻结几何换算，行被虚拟化重建/卸载不影响进行中的拖拽；同时提供 bounded（点击/创建钳行内）与 unbounded（播放头/范围拖拽跨行）两套时间映射，杜绝"拖到行边缘跳到下一行开头"的经典 bug
- **peaks 共享**：行组件不各自 fetch——peaks 提升到编排层单次解码共享 buffer（MAW 同款：整条波形一次解码，每行绘制时从共享 buffer 取区间算包络），行组件注入只读（风险 1 的解法，见 3.6）；**行包络按 `{rowIndex, widthPx, dpr, scale}` 记忆化**（MAW `getWaveformEnvelope` :3345-3377 同款），dpr cap 2
- **覆盖层刷新保 canvas**：字幕块增删/选中/状态刷新只动块 DOM 不重绘行 canvas（MAW `refreshCueOverlay` :3273-3291 同款）；滚动容器 `overscroll-behavior: contain` 防滚动链穿透
- **播放头行级化**：每行渲染条件 `currentTime ∈ [rowStart, rowEnd)`，行内百分比定位——与 MAW `positionPlayheads` 同构；**块 active 高亮与行级播放头共享同一 usePlaybackClock 时间源**（避免双时间来源漂移）；编排层不再渲染全局 PlayheadOverlay（basic 模式保留）
- **跟随策略三分**：用户手动滚动（`manualFollowUntil = now+3000`，程序化滚动不打断）/ 播放跟随（**换行才判定**，35% 偏置）/ 跳转 revealTime（45% 偏置 + 舒适区免滚）——三个滚动意图用时间戳 + 回环抑制标志解耦
- **跨行字幕**：块按行窗口裁剪渲染两份 + `continues-from/to` 类；trim 手柄只在行内边缘渲染（照抄 MAW :3133-3142 规则）；相接侧去圆角保持视觉连续（MAW waveform.css:808-817 同款）
- **`ScrollbarStrip` 转型迷你总览条**（不退役）：multi 模式下改渲染"全片缩略条"——显示视口覆盖区间 + 播放头位置，点击/拖拽跳转。这是对 MAW 已知槽点（无总览 mini-map，长视频只能逐行滚）的**反向超越设计**；basic 模式保留现状语义

### 3.6 风险清单

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 1 | N 个行组件各自 fetch peaks JSON → 重复网络/解析开销 | 高 | peaks 提升到编排层单次解码共享 buffer，行组件注入只读；M11-3 sidecar 契约不变 |
| 2 | 行挂载/卸载的 canvas 重绘成本（滚动时连续 mount） | 中 | rAF 调度统一合帧 + 160ms debounce（高回报率滚轮只累计净步数）；视口 ±2 缓冲；Vue keyed 回收；行包络记忆化（同几何零重算）；覆盖层刷新保 canvas；不达标再上 MAW 式 DOM 保留后手 |
| 3 | **虚拟行重建 × 进行中拖拽**：拖拽状态若留在组件实例内，行 unmount 即丢状态 | 高 | 拖拽几何快照契约——拖拽状态上提到 composable/store，pointerdown 冻结行几何，虚拟化对交互透明（MAW :3621-3629 已验证此路可行） |

### 3.7 验收总纲

- **P0.5 收口批验收**：pytest 锚定「update_segment 联动路径 patch 携带 tracks/bindings 层」；vitest/集成测试锚定「真实调用点的三层原子 undo/redo 对称」（非手工构造）；副轨 trim 在 UI 层可用（TrackLane→SegmentBlock updateTime 下传 + SegmentBlock trim 生效用例）；`export_track_srt` 删除后全量回归绿
- **vitest 新增**：行几何内核逐函数（行映射/虚拟窗边界/舒适区三路径/末行缩短/恢复量化——**移植 MAW test_waveform_js.mjs:283-289 等既有用例**）、bounded/unbounded 双映射、行级播放头可见性、跨行字幕裁剪与手柄规则、拖拽几何快照（行卸载后拖拽继续）、设置持久化 round-trip
- **性能不回退**（对照 docs/3.0.1/perf-baseline.md）：千段项目滚动/播放/行重排帧率不低于基线；单行挂载重绘 p95 目标 < 8ms（rAF 合帧后单帧预算内）；现有 453 前端测试全绿
- **门禁沿用**：pytest 702 / vitest 全绿 / ruff 0 / eslint 0 / events-diff 空（本版零新增事件、零 schema 变更红线；行设置走 localStorage 不入 project.json）
- **真机回归**：双平台——行区滚轮/触控板（deltaMode）、Ctrl+滚轮换行秒数时播放行锚定、舒适区跟随手感、basic/multi 模式切换往返、跨行 trim、跨行拖播放头
