## 2. T1：列表区「编辑字幕」按钮对副轨生效

### 2.1 现状与根因（已精确定位，非缺陷而是书面裁决的反转）

「编辑字幕」按钮位于字幕列表头部（`frontend/src/components/workspace/Timeline.vue:566-573`），切换 `globalEditMode`（定义于 `WorkspacePage.vue:367`）。按钮本身对任何轨道都正常翻转（所以用户说「退出编辑可用」——状态切换是好的），**但副轨侧没有任何监听者**。

`globalEditMode` 的传播路径与各消费点：

```
WorkspacePage.vue:367 (定义)
├─ :1399 → Timeline.vue:654 → TranscriptRow（列表行）
├─ :1465 → WaveformEditor.vue:65
│    ├─ :1110 → WaveformRow:318 → SegmentBlocksLayer（multi 主轨块）
│    ├─ :1184 → SegmentBlocksLayer（basic 主轨块）
│    └─ TrackLane（basic :1225-1240 与 multi 经 WaveformRow:339-358）→ 不接收该 prop
└─ SegmentBlock.vue:38/63 收到 prop 但内部零使用（死 prop）
```

根因一（列表侧，用户所见现象的直接原因）——`TranscriptRow.vue:327-337` 的**有意豁免**：

```ts
// v3.0.3 M1-3: track rows opt out of the global-edit sweep -- they enter
// editing only via dblclick / their own menu item.
onMounted(() => {
  if (props.globalEditMode && !isTrackVariant.value) startEdit()   // :328
})
watch(() => props.globalEditMode, (val) => {
  if (isTrackVariant.value) return          // :331 ← 副轨行在此被短路
  if (val && !isEditingText.value) startEdit()
  else if (!val && isEditingText.value) saveEdit()
})
```

- 这是 3.0.3 M1-3 的**书面裁决**（docs/3.0.3/record-3.0.3-P1-3.md:10），且有测试固化对立断言（`TranscriptRow.test.ts:270-276` "never enters text edit under globalEditMode"）——解除时需一并反转测试。
- 主轨语义 = 一键进入全列行内编辑、退出时批量保存；副轨行被裁决为只走双击/右键「编辑」单项入口。副作用即用户所见：切到副轨后按钮按了没反应。

根因二（波形侧，一致性缺口）：TrackLane 根本不接收 `globalEditMode` → 副轨块 trim **恒可用**（无编辑模式守卫），lane 块右键菜单（删除此条字幕/清空此轨/删除此轨，`TrackLane.vue:186-216`）也无守卫——与主轨块菜单被 `SegmentBlocksLayer.vue:195-231` 阻断形成**主/副不对称**。

### 2.2 副轨编辑通路就绪度

全部底层通路 3.0.3 已交付：行内文本/时间戳编辑器、`track-text`/`track-time` 事件（`Timeline.vue:662-663`）、useTrackEdit 内核（乐观更新 + 300ms 防抖合并 + 失败回滚 + 撤销谓词表，列表/波形双入口共用）、后端 `update_track_segment`（`allowed_fields={"start","end","text"}`，project_service.py:1382，clamp + 最小时长 + 同轨重叠拒绝 + 绑定偏移重建）。撤销捕获零新增工作（`undoListTrackCapture.test.ts` 覆盖谓词表）。**缺的只是把扫掠行为对 track 行打开这一个开关位。**

### 2.3 模拟用户故事

- US-T1-1（双语校对者）：「我切到英文字幕轨，点『编辑字幕』，希望整列直接进入可编辑状态，逐条校对完点『退出编辑』一次性保存——和主轨一样的手感。现在按钮点下去像坏了。」
- US-T1-2（对照校对者）：「我在主副轨之间来回切，希望编辑态跟着视图走：主轨在编辑态，切到副轨也想直接改；切回主轨不能丢我的编辑状态。」
- US-T1-3（谨慎型用户）：「退出编辑 = 批量提交。我希望副轨也遵守同一套：没改的行不产生 patch、非法输入回滚 + toast、undo 一次回退整批。」

### 2.4 方案选项

| 方案 | 内容 | 规模 | 评价 |
|---|---|---|---|

### 2.5 风险与边界

- 退出编辑 = 批量 save：多行同时改动产生多次防抖合并后的 patch——与主轨行为一致，无新风险。
- 列表切换丢草稿边界（`Timeline.vue:247-258` flush-on-switch）：track 行进入扫掠后，切换轨视图时未决防抖需先 flush——机制已有，需补扫掠路径断言。
- 防抖 300ms 内 undo 竞态：既有已知项，不因本改动扩大。
- 主轨零回退：改动点全部在 `isTrackVariant` 分支内，主轨路径 diff 为零。
- 测试缺口：波形五组件 vitest 中 `globalEditMode` 零覆盖；「按钮开启后副轨行进编辑」无测试（现有断言相反）；lane 菜单守卫无测试（若做方案 B）。

### 3.2 「应该开也只开纠错」裁决的技术依据

1. **删除类 AI（smart_delete/highlight）产出 EditDecision，驱动视频剪辑导出，而剪辑管线是主轨契约**：排序不变量 "MAIN TRACK ONLY by contract"（project_service.py:123-125）；导出取 `timeline.transcript.segments`+edits（main.py:442）；SubtitleTrack docstring 明文 "merge / edit-decision systems can never match them against main-track segments"（models.py:145-147）。副轨删除建议无处落地或污染主轨 edit 模型。
2. **存储容器无 per-track 槽位**：AnalysisData/edits/llm_prompts 全挂 Timeline 级（models.py:331-350）；给副轨开删除/精华需 schema 变更 + 剪辑/导出/回滚链路全面改造，规模 L 且收益为负。
3. **纠错是唯一「纯文本、不动时间轴、不进剪辑模型」的 AI**：只改 text（+words reattach），副轨 text 写回通道已就绪已测（`update_track_segment` allowed_fields 含 text；PRD-v3.0.3 R1.3 "后端 text 路径已就绪"），与剪辑语义零耦合。
4. 语义搜索无害（只读）但轨模式下显示通路已错位（X2），属独立修复项，不构成「开放」理由。
5. 工作流步骤建议仍锁主轨（回滚层不含 tracks，workflow_engine.py:282-287；与裁决一致）。

### 4.2 数据流设计建议

```
用户入口（AIAssistantPanel 卡片 / 工具栏「翻译为新副轨」）
  → start_translation(target_language, …)（新 expose）
      → create_task("llm_translation", {timeline_id, target_language, track_name?})
  → _handle_translation（新 task handler，照 :889-990 模式）
      1. 读主轨 subtitle segments（排除已确认删除段，语义对齐导出映射）
      2. 复刻纠错分批：batch_size 30（config.py:70）+ 字符预算 4000（:77）
         + 前后 ctx 条（默认 5，:71）+ 并发 5（:74）+ opaque id t1..tN
         + 4 层 JSON 解析兜底 + BatchLedger + 每批一次重试 + 连续 429 转串行
      3. 【与纠错的关键差异】纠错 prompt 是「无需修正不输出」；翻译必须每条输出
         → coverage 校验反向：输出 id 集合 ≠ 目标 id 集合的批记入 ledger 失败
      4. 跨批一致性：上一批末尾 1-2 条已定稿译文随下批 payload 携带（滑动窗口）
      5. 全部批次成功后一次性落盘（后台线程，同 correction 模式）：
         新批量写方法（照 import_srt_as_track :679-693 的 transcript.model_copy 整体替换写法）：
         add_track(role="translation") + N 段 + 按 id 精确 1:1 建 offset=0 bindings
         + 单个 _success_patch(tracks=…, bindings=…)（project_service.py:137-155）保证 undo/redo 原子
      6. 返回带 project 的 result（task:completed 自动剥离 → 前端 get_project 刷新）
         + emit llm:translation_completed（events.py/events.ts 双侧登记）+ llm:token_usage
```

**关键设计裁决建议**：

1. **不要循环调 `add_track_segment`**：一段一 patch，千条 = 1000 次桥接往返 + 1000 个 revision + undo 污染（3.0.2 smoke 为此把「清空」改成一次操作，`clear_track_segment` ts 注释自证此坑）。必须新增批量写方法。
2. **必须绑定主轨段（offset=0）**：绑定后自动获得「主轨改时间→译文跟随、播放双语第二行、双语 SRT 导出」三项既有能力；不绑定则双语导出直接拿不到译文（BOUND-only 硬条件）。
3. **同 start/end**：译文条目直接复制主轨时间（行业常态，`import_srt_as_track` 同款）。
4. **同目标语言已有翻译轨**：MVP 建议拒绝并提示（可先清空/删轨），不做自动合并/增量重译（登记后续增强：ledger.uncovered 补译入口）。
5. **undo 时序**：前端必须在任务 start 前 `pushSnapshot(["tracks","bindings"], "AI翻译副轨")`——后台线程完成写入时前端无法插入快照。
6. **进度**：走通用 `task:progress`（批粒度百分比）；可选加 `llm:translation_progress` 做逐批流式预览（照 highlight 模式）。

## 5. T4：「剪辑范围」承载 + 3.0.x 回归检查

### 5.2 现有机制盘点

| 机制 | 数据位置 | 创建入口 | 导出参与 | 关键 file:line |
|---|---|---|---|---|
| EditDecision range | `timeline.edits` | 后端 2 生产者（subtitle_trim / 高光虚拟），**前端 0 入口** | **唯一被导出消费的范围载体** | models.py:99-115；project_service.py:2560-2661；export_service.py:599-606 |

| 副轨段 | tracks[i].segments | 列表空态/右键（波形 lane 建段断线 = X1） | **完全不参与视频/音频裁剪**（export 只读主轨 segments + edits） | project_service.py:1544-1605 |

**约束域语义（方案取舍的关键事实）**：约束内核是**按轨道域独立生效的一维规则**，无跨域（主轨↔副轨）规则——主轨域内 subtitle 与 silence 互为邻居（test_track_linkage.py:114 钉死）；副轨域内只查同轨兄弟段（project_service.py:1577-1585）；**副轨段与主轨段任意重叠完全合法**。但副轨块当范围标记不可行：导出不消费副轨 →「标了但导出没剪」。

**约束是编辑期行为而非存储不变量**：`add_segment` / `update_transcript` / `add_silence_results` / split/merge 均无重叠检查；前端 basic 模式空白点击建 0.5s 块（SegmentBlocksLayer.vue:164-166）**不 clamp**——点到既有块旁可造出重叠数据（约束体系的真实漏洞面，见 5.4 缺口清单）。

### 5.3 三方案对比

| | 方案 A：专用「剪辑范围轨」 | 方案 B：特殊选区（波形框选/时间码 → 生成 range decision） | 方案 C：range decision 第一公民 UI（复用既有 edits 层） |
|---|---|---|---|
| 数据 | 新 track role（如 `role="marker"`）或新实体 | 零新增（创建即转 EditDecision） | 零 schema 变更 |
| 导出 | ⚠️ **最大缺口**：export_video/audio/srt 全部只认 `timeline.edits`，必须新增「marker 轨→删除区间」翻译层或影子 edit | 天然参与导出（落 edits 后） | **天然正确**：`_get_confirmed_deletions` 消费任意 confirmed delete；v2.3.1 起 subtitle_trim 已验证全链 |
| 撤销 | tracks/bindings 层（先例有） | 临时态无需 undo；产物走 `["edits"]` | `pushSnapshot(["edits"])` 全链路现成（useWorkspaceActions.ts:652、useAnalysis.ts:73） |

| 前端挂点 | TrackLane 复用 + 选择器 + 导出桥 | **现成死代码挂点**：`selectedRange` ref（useSegmentEdit.ts:85、102-104）只写不读；Shift-marquee 手势已有（WaveformEditor :687-709） | 需 1 个后端 expose（如 `add_range_decision`，直接 push EditDecision，~半天）+ 手势/管理 UI |

| 后端改动 | 大（模型+导出翻译+UI 三层） | 近零 | 小（1 expose；模型/patch/导出零改动） |

**推荐：C 为主 + B 作为 C 的输入手势合并实施**（框选/时间码 → 建 range decision，顺手激活 selectedRange 死代码）；A 仅当产品要求「范围标记像副轨一样轨道化管理（折叠/重命名/整轨删除）」时才值得——若用「影子 range edit」实现导出，A 退化为 C 的皮肤，纯增成本。

组合方案用户故事化交互：

1. 波形区框选（Shift-marquee 复用或专用手势，注意与 Ctrl-create 建段手势的模式裁决，见 §8-Q11）→ 确认气泡（删除/保留 + 备注）→ `add_range_decision` → pending range decision → 斜纹覆层即刻可见 → 确认后进 deleteRanges（WorkspacePage.vue:295-300 过滤条件需扩 pending range，可选）。
2. 建议面板新增「手动范围」分组：逐条确认/拒绝/删除，与静音/智能删除分组并列（现仅列两源，SuggestionPanel.vue:63-99）。
3. 时间码精确创建：工具栏入口弹两个时间码输入（口播场景常需精确起止）。
4. 保留语义（如需）：subtitle_trim 的 keep 集合计算（project_service.py:2588-2596）可感知用户 range keep 标记——这是 2.x 占位块「撑住间隙」习惯的现代化等价，需产品裁决（§8-Q10）。
