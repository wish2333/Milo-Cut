## 0. 结论

本次完成了不依赖 Python、FFmpeg、真实媒体文件或外部 API 的浏览器 Demo，并接入 Netlify 静态部署配置。Demo 复用 Milo-Cut v2.4.0 工作台视觉系统，支持模拟媒体预览、字幕编辑、AI 建议、字幕纠错、工作流冲突解决和模拟导出；窄屏下切换到单列紧凑工作区，移动端保留字幕核心区域和底部功能导航。Demo 设置页的 LLM 配置字段也已补齐并增加空值保护。前端测试、生产构建、lint 和差异检查全部通过。

## 2. 架构决策

### 2.1 双 runtime，桌面协议不变

`VITE_DEMO_MODE=true` 时，`bridge.ts` 将调用路由到浏览器内存 Demo bridge；桌面版继续使用 `window.pywebview.api`。Demo 逻辑集中在 `frontend/src/demo/`，避免把浏览器 mock 分散到业务组件中。

### 2.2 无媒体资源的演示路径

模拟媒体画面、播放头和波形全部在浏览器内生成，不提交 `.mp4`、音频或 waveform JSON，也不触发真实文件系统和外部 LLM 请求。

### 2.3 桌面宽屏与窄屏分层

宽度大于等于 1200px 时继续使用完整桌面工作台；更窄的窗口使用单列 Demo 工作区，保留字幕、建议、AI、纠错和导出路径，避免通过硬缩放压缩原有双栏布局。

### 2.4 Mock 返回完整配置

Demo bridge 的 `get_settings` 返回完整 `AppSettings`，同时组件侧对可选 URL 做空值防护，避免静态 Demo 因不完整 mock 数据触发运行时错误。

## 4. 已知限制

1. Demo 不提供真实视频上传、ASR、LLM 请求、FFmpeg 编码、媒体导出和项目持久化。
2. Netlify 部署配置已完成，但本次不代替用户执行 Netlify 账号绑定和线上 Deploy Preview。
3. 尚未在真实 PyWebView 窗口中执行 macOS/Windows 截图回归；桌面 bridge 路径未修改。
4. Demo 使用确定性内存状态，刷新页面会恢复初始 fixture。
5. lint 仍保留 4 条既有 warning，未扩大本次 Demo 范围处理。

## 5. 迁移与升级说明

- 无数据格式变化。
- 无 backend API 或桌面 bridge 协议变化。
- Netlify 构建需要 `VITE_DEMO_MODE=true` 和 `BUN_VERSION=1.3.10`，已写入 `netlify.toml`。
- 用户本地预览使用 `VITE_DEMO_MODE=true bun run dev`。
- 无新增运行时依赖。
